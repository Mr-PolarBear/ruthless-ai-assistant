# 功能说明文档：隐藏与总结

**最后更新时间**: 2026年8月22日

**负责人**: 小鸡

---

本文档详细说明“快速隐藏”和“隐藏与总结”两大相关功能的实现逻辑与关键代码，旨在为后续的维护和迭代提供清晰的指引。

## 一、 功能概述

该系列功能允许用户通过两种方式对消息楼层进行“隐藏”标记，并能对隐藏的楼层进行独立的总结。

1.  **快速隐藏**：在任意一条消息上，提供一个“快速隐藏”按钮，用户点击后可一键标记从第1楼到当前楼层的全部消息为“已隐藏”。
2.  **隐藏与总结**：提供一个独立的设置弹窗，用户可以精确地设置要隐藏的楼层范围、自定义总结提示词，并调用AI对该范围内的消息进行总结。

核心设计思想是：**所有“隐藏”操作仅为视觉标记，不影响消息的实际内容和可交互性**。所有配置都与特定会话绑定，存储于`localStorage`中。

---

## 二、 快速隐藏 (Quick Hide)

### 1. 功能入口

在每条消息气泡（包括用户提问与 AI 回答）中，工具栏均提供“快速隐藏”按钮 (`.quick-hide-btn`)。

### 2. 核心逻辑

1.  **打开弹窗**：用户点击“快速隐藏”按钮后，触发 `handleChatMessageActions` 函数。
    *   该函数首先调用 `e.stopPropagation()` **阻止事件冒泡**，这是为了防止点击事件意外触发页面上其他监听器，导致弹窗刚打开就关闭的“灵异事件”。
    *   然后调用 `openQuickHideModal(floor)` 打开确认弹窗，并将当前楼层号传入。
    *   弹窗内会**实时统计并高亮展示当前分支已隐藏的所有楼层概览**（包括楼层总数与区间压缩标签，如 `第 1 ~ 3 楼`、`第 5 楼`），状态一目了然。

2.  **用户选择隐藏模式**：
    *   **单楼层独立切换** (`#quick-hide-single-btn`)：
        *   **未隐藏时**显示【隐藏当前楼层】：点击后在当前消息对象上标记 `msg.hidden = true`，并同步更新隐藏楼层集合 `hiddenFloors`。**精准绑定消息对象，重新生成或新建分支时新节点不会被误标记，且完全不影响其他已隐藏楼层**。
        *   **已隐藏时**显示【取消隐藏当前楼层】：点击后将当前消息标记为 `msg.hidden = false`，并从隐藏集合中剔除。
    *   **隐藏1至本楼** (`#quick-hide-confirm-btn`)：弹出防误触二次确认框，用户确认后将从第1楼到当前楼层的消息对象批量标记为 `hidden = true`。
    *   **区间快捷隐藏** (`#quick-hide-range-btn`)：支持自定义输入 `第 [Start] 至 [End] 楼`，点击【隐藏此区间】后弹出二次确认框，用户确认后将该区间范围内的消息增量批量标记为 `hidden = true`。**增量合并隐藏，绝不影响或取消其他已隐藏的楼层**。
    *   该函数会持久化保存会话消息数据与 `state.hideSummary`，并立即保存到 `IndexedDB` 与 `localStorage`。
    *   随后，调用 `renderChatMessages({ updateVisibilityOnly: true })`，**执行局部刷新**。
    *   最后调用 `closeModalWithAnimation(dom.quickHideModal)` 关闭弹窗。

3.  **局部刷新**：`renderChatMessages` 函数接收到 `updateVisibilityOnly: true` 参数后，会进入一种特殊的、更高效的渲染模式。
    *   它**不会**重绘整个消息列表，而是遍历当前DOM中已存在的每一条消息。
    *   通过 `isMessageHidden(msg, floor, summaryConfig)` 优先判断消息自身的 `hidden` 状态是否为隐藏。
    *   如果需要，它会动态地在消息的头部 (`.sender-line`) 添加或移除一个“已隐藏”的提示标签 (`.hide-summary-tip`)。
    *   **关键**：此过程**不会**隐藏消息的任何部分（如内容、按钮等），仅做标记添加/移除操作。

4.  **取消隐藏**：用户在弹窗中点击【取消所有隐藏】按钮 (`#quick-hide-reset-btn`)。
    *   弹出防误触二次确认框，确认后清空当前分支上所有消息的 `hidden` 属性，清空 `hiddenFloors: []` 并设置 `enabled: false`，然后执行局部刷新。

// 监听器: 单楼层独立切换（精准绑定消息对象自身，分支与重新生成状态隔离）
dom.quickHideSingleBtn.addEventListener('click', () => {
    const floor = parseInt(dom.quickHideModal.dataset.floor, 10);
    const isFloorHidden = dom.quickHideModal.dataset.floorHidden === '1';
    const conv = state.conversations[state.currentConversationId];
    if (floor && conv) {
        const activeBranch = conv.branches ? conv.branches[conv.activeBranchIndex] : [];
        const targetMsg = activeBranch ? activeBranch[floor - 1] : null;

        if (isFloorHidden) {
            if (targetMsg) targetMsg.hidden = false;
        } else {
            if (targetMsg) targetMsg.hidden = true;
        }

        const hiddenFloors = activeBranch
            ? activeBranch.map((m, i) => (m.hidden ? i + 1 : null)).filter(Boolean)
            : [];

        setHideSummaryForCurrentConversation({
            hiddenFloors,
            start: hiddenFloors.length > 0 ? Math.min(...hiddenFloors) : 1,
            end: hiddenFloors.length > 0 ? Math.max(...hiddenFloors) : 1,
            enabled: hiddenFloors.length > 0
        });
        saveConversation(conv.id, conv);
        renderChatMessages({ updateVisibilityOnly: true });
        if (window.updateHideSummaryBtnColor) window.updateHideSummaryBtnColor();
        closeModalWithAnimation(dom.quickHideModal);
    }
});

// 监听器: 隐藏1至本楼
dom.quickHideConfirmBtn.addEventListener('click', () => {
    const floor = parseInt(dom.quickHideModal.dataset.floor, 10);
    if (floor) {
        setHideSummaryForCurrentConversation({ start: 1, end: floor, enabled: true });
        renderChatMessages({ updateVisibilityOnly: true });
        if (window.updateHideSummaryBtnColor) window.updateHideSummaryBtnColor();
        closeModalWithAnimation(dom.quickHideModal);
    }
});
```

## 三、 会话记忆与智能总结 (Conversation Memory & Summary)

### 1. 功能入口

侧边栏顶部“新的对话”操作行中，位于工具箱右侧的“隐藏与总结”按钮 (`#hide-summary-btn`)。

### 2. 核心设计与重构逻辑

1.  **职责彻底解耦**：
    *   弹窗不再管理隐藏区间的数字输入，所有楼层隐藏由消息气泡上的【快速隐藏】独立精准管理。
    *   本弹窗专注于对**当前活跃分支中的未隐藏（可见）消息**进行长期记忆提炼与智能总结。

2.  **自动总结触发机制 (`summary-manager.js`)**：
    *   在流式响应结束或非流式响应完成时，调用 `checkAndTriggerAutoSummary(convId, branchIndex)`。
    *   **触发模式一（按楼层数）**：当当前分支未隐藏可见消息数 $\ge N$ 楼（默认 10 楼）时自动在后台静默发起总结请求。
    *   **触发模式二（按 Token 阈值）**：当当前分支未隐藏可见消息预估 Token $\ge N$ 个（默认 4000 Tokens）时自动触发总结。
    *   **总结后抛弃已总结楼层**：若勾选【总结完成后自动隐藏被总结的历史楼层】，系统在总结成功后会自动将该批参与总结的消息置为 `msg.hidden = true`，并保存会话并局部刷新。

3.  **系统级记忆注入 (`api-common.js`)**：
    *   当开启记忆总结且存在总结文本时，在发送给大模型的上下文最前部注入系统级记忆：
        `本条消息属于对历史对话内容的长期记忆总结，你必须阅读后作为上下文参考再进行回答：[总结内容]`
    *   结合最近消息数量限制 (`messageLimit`)，截取最近可见消息，达成无限长对话上下文无损滚动压缩。

4.  **清空总结撤销回滚机制 (`modal-events.js`)**：
    *   点击【清空总结】时自动建立当前会话的内容备份，并动态将按钮切换为【撤销清空】；
    *   误操作或需要恢复时，点击【撤销清空】可一键原样恢复历史总结文本。

5.  **后台总结并发冲突弹窗与实时秒表流式预览 (`auto-summary-conflict-modal.js`)**：
    *   当后台正在自动总结时用户发出新消息，系统自动拦截并弹出冲突处理窗口；
    *   **精准已耗时秒表**：实时刷新 `⏱️ 已耗时 X.Xs`，客观准确展示后台执行时长；
    *   **实时流式提炼预览**：订阅后台 `onChunk` 流式管道，打字机实时滚动展示模型正在提炼的记忆内容；
    *   **三维操作决策**：
        *   【等待完成自动发】：总结一结束自动将消息带上最新记忆无缝发出；
        *   【立即发送(跳过)】：不等总结，直接以当前上下文发出；
        *   【取消本次发送】：放弃发送，消息完整保留在输入框。

6.  **实际发送 Token 徽章与多维度统计明细 (`ui-updater.js` & `utils.js`)**：
    *   **主界面徽章 (`#session-token-badge`)**：仅展示当前实际发送给大模型的预估 Token 数（过滤已隐藏楼层、截取最近消息限制，并计入注入的系统总结记忆）；
    *   **浮窗 Tooltip 提示**：鼠标悬停显示完整的 `实际发送: A Tokens (总预估: B / 已隐藏: C)` 详尽明细；
    *   **弹窗多维同步**：在【记忆与智能总结】弹窗顶部及【会话数据详情】弹窗中同步展示实际发送 Token 与已隐藏 Token 对比。

7.  **历史总结版本全生命周期与回滚确认 (`summary-history-modal.js`)**：
    *   **快照自动沉淀**：每次手动保存或自动总结成功时，自动将当时的总结文本与隐藏楼层集合存入 `history` 快照树（上限 30 条）；
    *   **版本管理面板**：支持查看历史版本的生成时间、来源类型（自动/手动）、字数与对应隐藏楼层概览，支持**单条删除**与**一键清空**；
    *   **交互回滚确认**：点击回滚时弹出二次选择框，让用户自主决定是【同步恢复楼层隐藏与总结】（完全还原到该时刻）还是【仅恢复总结文本】（不改变当前隐藏状态）。

8.  **归档时保留最后 $K$ 楼不隐藏机制 (`summary-manager.js`)**：
    *   在总结归档时支持配置 `☑ 归档时保留最后 [ 2 ] 楼不隐藏 (用于AI参考格式与近期语境)`；
    *   算法在自动隐藏时截取排除最后 $K$ 条消息，确保大模型始终具备最近 1~2 轮的格式示范（如 JSON、Markdown 排版或特定语气）。

9.  **AI 输出期间输入框只读锁定保护与多会话隔离 (`ui-updater.js`)**：
    *   在主会话 AI 流式输出中或总结生成期间，自动将 `#hide-summary-result` 文本框设为 `readOnly = true` 并禁用保存/清空按钮，防止并发修改造成冲突覆盖；
    *   一旦生成结束或用户手动点击【停止】，系统自动解锁恢复编辑；
    *   **多会话编辑锁定状态隔离**：锁定判定严格校验 `state.autoSummarizingConvId === state.currentConversationId`，仅当后台自动总结的目标会话与用户当前正在查看的会话一致时才锁定编辑框。若会话 A 正在后台总结而用户切换到会话 B 打开弹窗，会话 B 的编辑框**完全正常可编辑**，不会因为会话 A 的后台任务而被误锁。

10. **当前隐藏楼层状态实时概览与即时自动刷新**：
    *   在【会话记忆与智能总结】弹窗顶部 Token 统计下方，增加当前已隐藏楼层横幅；
    *   **智能双模自适应区间压缩算法 (`formatHiddenFloorsBannerInfo`)**：
        1. **完美全覆盖**（无空洞）：展示连续区间 `第 1 ~ 500 楼 (共 500 层)`；
        2. **大面积隐藏 + 少量空洞**（如 500 楼中仅有不足 15 层或 $\le 25\%$ 未隐藏）：
           - **第一行**：展示最大跨度 `覆盖区间：第 1 ~ 500 楼 (已隐藏 490 层)`；
           - **第二行**：展开单行不换行、可横向平滑滚动的提示条 `⚠️ 区间内未隐藏 (10 层)：[第 50 楼] [第 72 ~ 75 楼] ...`，未隐藏楼层自身同样进行连续区间压缩并配有微胶囊 Badge，永不撑爆弹窗高度；
        3. **多段完全离散隐藏**（如仅隐藏 1~10 楼和 490~500 楼）：自动合并展示紧凑的多段区间 `第 1 ~ 10 楼、第 490 ~ 500 楼 (共 20 层)`，避免误导；
        4. **全可见**：无隐藏时明确显示 `无隐藏楼层 (全部可见)`，自动收起第二行。
    *   无论是手动总结还是后台自动总结完成，弹窗内**无需重新打开即可即时刷新已隐藏楼层明细与实际/隐藏 Token 统计**；
    *   **`window.refreshHideSummaryModalViews()` 全景刷新接口**：暴露给外部调用的一站式刷新函数，执行链路包括：
        1. 重新读取并标准化当前会话的 `hideSummary` 配置；
        2. 调用 `updateHideSummaryBannerAndStats()` 刷新 Token 概览与隐藏楼层横幅；
        3. 调用 `switchMode()` 将最新记忆内容灌入对应模式视图（递归文本框 / 卡片流 / 双表 Grid）；
        4. 刷新历史版本角标数量；
        5. 调用 `updateSummaryEditorLockState()` 恢复或更新编辑框锁定状态；
        6. 调用 `updateHideSummaryCharCounters()` 重算字数统计。
    *   **触发时机**：后台自动总结的 `finally` 块、手动总结成功后、历史版本回滚后均自动调用该接口。

11. **后台自动总结实时感知与图标转圈动画 (`ui-updater.js` & `summary-manager.js`)**：
    *   **即时启动提示**：自动总结触发时，页面立即弹出 Toast 提示 `🔄 开始进行自动记忆总结...`；
    *   **图标转圈动画**：侧边栏【隐藏与总结】眼睛按钮进入高亮呼吸并持续旋转动画（`.summarizing-spinning`）；
    *   **跨会话状态隔离**：全局绑定 `state.autoSummarizingConvId`，切换到其他会话时转圈动画立即移除，切回总结会话时动画即时恢复，杜绝串台误导；
    *   **`autoSummaryContext` 全局上下文单例** (`summary-manager.js:621-627`)：
        *   `convId`：当前正在自动总结的会话 ID；
        *   `startTime`：总结开始时间戳（用于秒表计时）；
        *   `currentStreamText`：实时流式输出文本缓存（每次 `onChunk` 回调时更新）；
        *   `listeners`：`Set` 类型的并发订阅者集合，每个订阅者对象支持 `{ onChunk, onFinish, onError }` 三个回调；
        *   `abortController`：`AbortController` 实例，用于中断正在进行的总结请求。
    *   **弹窗内实时流式打字机同步** (`modal-events.js`)：
        *   系统在初始化时向 `autoSummaryContext.listeners` 注册一个**常驻监听器**，生命周期与弹窗共存；
        *   `onChunk(delta, fullText)` 回调：当弹窗处于打开状态（`dom.hideSummaryModal.style.display !== 'none'`）且当前会话与总结会话一致时，实时将 `fullText` 写入对应模式的输入区（递归模式 → `#hide-summary-result`，表格源码模式 → `#summary-table-raw-textarea`）并自动滚底，同时刷新字数统计；
        *   `onFinish()` 回调：后台总结成功完成时，若弹窗处于打开状态，自动调用 `window.refreshHideSummaryModalViews()` 执行全景刷新（隐藏楼层横幅、Token 概览、记忆内容、编辑锁定状态等一次性全量更新）；
        *   `onError()` 回调：总结出错时解锁编辑框。
    *   **弹窗打开时秒级载入当前流式进度**：
        *   用户在后台正在自动总结期间点击打开总结弹窗时，系统检测 `state.isAutoSummarizing && autoSummaryContext.convId === convId`，若已有流式缓存文本 `autoSummaryContext.currentStreamText`，**立即将已输出的内容一次性灌入文本框**，用户无需等待即可看到模型当前已提炼到的进度；
        *   后续 `onChunk` 回调持续追加增量文本，实现无缝打字机续接。
    *   **多会话完全物理隔离**：
        *   所有流式写入、弹窗刷新均严格校验 `state.currentConversationId === autoSummaryContext.convId`，确保会话 A 的流式输出**绝不可能串入**会话 B 的弹窗文本框；
        *   会话 A 在后台总结完成后的 `finally` 块中触发 `refreshHideSummaryModalViews()`，但由于此时用户若在会话 B，该刷新读取的是会话 B 的数据，不会产生串台问题。

12. **3 种独立会话记忆模式体系 (`summary-manager.js`, `modal-events.js`, `modals.html`)**：
    *   **模式一：🔄 递归滚动记忆 (`recursive`)**：
        *   **机制**：不限制文本最大字数。每次总结时，系统会将当前**已有的记忆总结**连同未隐藏的新对话楼层一并作为前置背景提供给 AI，要求 AI 在全量融合已有记忆的基础上提炼最新全景大纲。
        *   **系统提示词注入格式**：
            `本条消息属于对历史对话内容的长期记忆总结，你必须阅读后作为上下文参考再进行回答：\n${summary}`
    *   **模式二：📑 列表拼接记忆 (`append`)**：
        *   **机制**：增量追加模式。每次只对未隐藏的新楼层进行提炼，生成一个时间段的记忆卡片（含生成时间、楼层范围与内容）；
        *   **UI 交互**：提供卡片流管理视图，支持用户自由编辑任意片段或删除单条；
        *   **系统提示词注入格式**：发送给 AI 时，将所有历史卡片按阶段顺序拼接为一个连续的列表文本发送。
            `本条消息属于对历史对话内容的长期记忆摘要集（按阶段排序）：\n[阶段 1 (第 1~10 楼)]: ...\n[阶段 2 (第 11~20 楼)]: ...`
    *   **模式三：⚔️ 跑团双表记忆 (`table`)**：
        *   **机制**：专为 TRPG / 角色扮演与复杂世界线设定打造，维护两大结构化数据表：
            1. **📜 历史记录表**：记录 `时间 | 地点 | 涉及角色 | 事件 | 涉及物品`；
            2. **👤 角色信息表**：记录 `姓名 | 简介 | 最新状态说明 | 持有关键道具`。
        *   **增量演进与双表解析**：总结时将原有的两个 Markdown 表格发给 AI，要求 AI 对历史记录表只追加新发生的重大事件，对角色信息表根据最新剧情更新角色状态与道具；
        *   **UI 可视化表格与源码双向切换**：提供交互式输入表格（支持随时添加行、删除行、单元格即时编辑），并支持一键切换至 Markdown 源码模式直接修改并双向反向解析；
        *   **放大编辑与多行行高自定义**：
            *   支持【⛶ 放大编辑 / 🗗 还原窗口】切换，桌面端支持超宽大屏（95vw / 1320px），手机端（≤768px）自适应全屏贴边铺满；
            *   工具栏支持【行高：1行/2行/3行/4行/6行】切换，单元格自动多行折行并持久化记忆；
        *   **系统提示词注入格式**：
            `本条消息属于对历史剧情与角色状态的长期记忆结构化表格，你必须严格遵循表中的世界线与状态设定：\n\n### 历史记录表\n| 时间 | 地点 | 涉及角色 | 事件 | 涉及物品 |\n...\n\n### 最新角色信息表\n| 姓名 | 简介 | 最新状态说明 | 持有关键道具 |\n...`
    *   **每种模式专属提示词与一键恢复**：
        *   3 种模式拥有独立的定制提示词存储，切换模式时自动读取对应的模式提示词；
        *   提供【🔄 恢复默认提示词】按钮，支持一键恢复该模式由架构师调优的官方默认提示词。

13. **已隐藏消息重发拦截与分叉记忆智能联动回滚机制 (`chat-events.js`, `summary-manager.js`, `branch-summary-confirm-modal.js`)**：
    *   **已隐藏消息重发防护**：
        *   当用户点击【从此重发 / 重新生成】时，系统首先检查目标消息自身的隐藏状态 (`isMessageHidden`)；
        *   若消息已被标记为隐藏，**立即拦截重发并弹出 Toast 警告**：`第 X 楼当前处于已隐藏状态，重发前请先取消该消息的隐藏（点击右侧 👁️ 图标即可解除）`，防止新分支产生不可见的逻辑混乱。
    *   **时间线因果一致性智能判定**：
        *   当用户在第 $K$ 楼分叉重发时，系统通过 `checkBranchMemoryStatus(convId, branchFloor)` 校验因果：
            *   若当前记忆生成发生楼层 $\le K$ 楼：说明记忆库中完全处于分叉点之前，**零因果冲突，0 弹窗打扰直接重发**；
            *   若当前记忆生成发生楼层 $> K$ 楼：说明当前记忆包含了分叉点之后的未来废弃剧情（例如 40 楼触发总结后回退到 30 楼重发）。
    *   **最优快照智能命中算法**：
        *   系统自动按时间倒序扫描历史快照树，寻找 $\text{maxFloor} \le K$ 的最新一条快照；
        *   **心血优先原则**：若用户在 20 楼自动总结后、28 楼手动修改过双表/设定并保存过，系统在 30 楼重发时将**精准命中 28 楼大爷最后手动保存的精修版**，而不是生硬回滚到 20 楼粗糙版。
    *   **傻瓜式一键决策弹窗 (`branch-summary-confirm-modal.js`)**：
        *   弹窗展示直观的 2 选 1 卡片：
            1. **✨ [推荐] 一键恢复至第 $K$ 楼记忆 (时间 来源) 并重发**：自动秒级恢复至该时刻的记忆快照并开启新分支，小白用户仅需点击一次即可无痛重发；
            2. **📦 保持当前记忆直接重发**：不修改记忆库，直接沿用当前记忆生成新分支；
            3. **取消重发**。

14. **会话导入/导出全维度联动 (`utils.js`, `export-modal.js`)**：
    *   在导出单个会话或全量打包导出时，`hideSummary` 完整打包并保留多模式状态、历史卡片、双表数据及快照版本树；
    *   在导入会话时，自动调用 `normalizeHideSummaryConfig` 对老版本旧数据进行向后兼容升级，确保平滑过渡到 3 模式体系。

// 格式化 3 种模式的记忆内容用于发送给大模型网关
export function formatMemoryForApi(config) {
    if (!config || !config.enabled) return '';
    const mode = config.memoryMode || 'recursive';

    if (mode === 'recursive') {
        const text = config.summary ? config.summary.trim() : '';
        return text ? `本条消息属于对历史对话内容的长期记忆总结，你必须阅读后作为上下文参考再进行回答：\n${text}` : '';
    } else if (mode === 'append') {
        const stitched = formatSummaryListToText(config.summaryList);
        return stitched ? `本条消息属于对历史对话内容的长期记忆摘要集（按阶段排序）：\n${stitched}` : '';
    } else if (mode === 'table') {
        const tablesMd = formatTablesToMarkdown(config.tableData?.eventHistory, config.tableData?.characterInfo);
        return tablesMd ? `本条消息属于对历史剧情与角色状态的长期记忆结构化表格，你必须严格遵循表中的世界线与状态设定：\n\n${tablesMd}` : '';
    }
    return '';
}
```

export function filterMessagesByHideSummary(allMessages, hideSummaryConfig, activeBranch) {
    const convId = state.currentConversationId;
    const hideSummaryConfigLocal = hideSummaryConfig || (state.hideSummary && state.hideSummary[convId]);

    const visibleMessages = allMessages.filter(msg => {
        const originalMsg = activeBranch && activeBranch[msg._idx - 1];
        return !isMessageHidden(originalMsg, msg._idx, hideSummaryConfigLocal);
    });

    if (hideSummaryConfigLocal && hideSummaryConfigLocal.enabled) {
        const memoryContent = formatMemoryForApi(hideSummaryConfigLocal);
        if (memoryContent && memoryContent.trim()) {
            const summaryMessage = {
                role: 'system',
                content: memoryContent.trim()
            };
            return [summaryMessage, ...visibleMessages];
        }
    }
    return visibleMessages;
}
