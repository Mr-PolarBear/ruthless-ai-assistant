# 360浏览器布局偏移修复方案

> 适用范围：360安全浏览器、360极速浏览器、以及其他基于旧版 Chromium 内核的国产浏览器  
> 文档版本：v1.0 | 2026-02-25

---

## 一、问题描述

在 360 浏览器中，页面整体布局会**向上偏移若干像素**（通常 5~15px），导致：

- 顶部导航栏/工具栏被部分裁切
- 底部输入区域或页脚向上移动，底部出现空白或被截断
- 在 Chrome、Edge 等标准浏览器中完全正常

**表现特征：**
- 清空缓存后加载静态 HTML，页面看起来正常
- **JS 加载执行后**，布局发生偏移
- 偏移量固定不变（不会随页面内容变化）

---

## 二、根因分析

### 2.1 360浏览器的内核问题

360浏览器底层使用的是**旧版 Chromium 内核**（通常是 69~86），与最新 Chrome/Edge（120+）在以下方面存在差异：

| 特性 | Chrome/Edge 120+ | 360浏览器(旧 Chromium) |
|------|-------------------|------------------------|
| `100vh` 计算 | 精确等于视口高度 | 可能包含/排除浏览器装饰区域 |
| `color-mix()` | ✅ 支持 | ❌ 不支持，fallback 可能导致异常 |
| CSS 变量嵌套 fallback | ✅ 正常 | ⚠️ 可能解析异常 |
| `backdrop-filter` | ✅ 正常 | ⚠️ 可能触发额外合成层 |

### 2.2 偏移的本质

360浏览器在渲染引擎层面对 `<html>` 和 `<body>` 的默认盒模型处理与标准浏览器不同。即使 CSS 已经设置了 `margin: 0; padding: 0;`，浏览器内部仍可能存在**隐式偏移**。这个偏移在 DOM 加载后、JS 执行过程中因 reflow 被"固化"，表现为整体布局上移。

---

## 三、尝试过但无效的方案

### ❌ 方案1：CSS 重置
```css
html, body { margin: 0; padding: 0; }
```
**无效原因**：偏移不是来自 CSS margin/padding，而是浏览器内核级别的渲染差异。

### ❌ 方案2：更换 vh 为百分比
```css
html { height: 100%; }
body { height: 100%; }
#app { height: 100%; }
```
**无效原因**：继承链虽然更稳定，但不能解决内核级别的隐式偏移。

### ❌ 方案3：设置 margin-top 补偿
```css
body { margin-top: 15px; }
```
**部分有效**：顶部可以修正，但由于 `height: 100vh` + `overflow: hidden`，底部会被截断更多。

---

## 四、最终解决方案 ✅

### 核心思路

**在页面完全加载后，用 JS 检测实际偏移量，通过 `transform: translateY()` 自动补偿。**

#### 为什么用 transform 而不是 margin？

| 方式 | 优点 | 缺点 |
|------|------|------|
| `margin-top` | 简单直接 | 会改变元素尺寸/位置，导致 `100vh` 的底部被截断 |
| `transform: translateY()` | **不改变元素的布局尺寸**，纯视觉平移 | 无 |

`transform` 只影响视觉渲染，不触发 reflow，不改变盒模型计算。元素的 `height: 100vh` 保持不变，上下同时修正。

### 代码实现

将以下代码放在项目的**入口 JS 文件**中（如 `main.js`）：

```javascript
/**
 * 360浏览器等旧 Chromium 内核布局偏移自动修复
 * 
 * 原理：页面完全加载后，检测主容器的实际位置偏移量。
 * 如果偏移超过阈值(3px)，使用 CSS transform 进行视觉补偿。
 * transform 不改变元素的布局尺寸，因此不会导致底部截断。
 * 
 * 适用条件：
 * - 项目使用 100vh 全屏布局
 * - 页面有一个主容器（如 #app）包裹全部内容
 * - 在标准浏览器中布局正常，仅在360等旧内核中偏移
 */
window.addEventListener('load', function() {
    // 获取主容器（根据实际项目修改选择器）
    var app = document.getElementById('app');
    if (!app) return;

    // 检测主容器顶部的实际偏移量
    var offset = app.getBoundingClientRect().top;

    // 阈值3px：排除正常的亚像素渲染差异
    if (Math.abs(offset) > 3) {
        console.warn('[布局修复] 检测到布局偏移 ' + offset + 'px，自动修复');
        app.style.transform = 'translateY(' + (-offset) + 'px)';
    }
});
```

### 使用说明

1. **复制上面的代码**到项目入口 JS 文件
2. **修改选择器**：将 `document.getElementById('app')` 改为你项目的主容器
3. **确保主容器**是包裹整个页面内容的最外层元素
4. 无需额外 CSS 配置，无需考虑浏览器检测

### 注意事项

- 该修复仅在偏移量 > 3px 时触发，不会影响正常浏览器
- `window.load` 事件在所有资源加载完毕后触发，确保检测准确
- console 会输出修复日志，便于调试确认
- 如果项目主容器已有 `transform` 属性，需要合并而非覆盖

---

## 五、验证方法

1. 在 360 浏览器中打开页面
2. 按 **F12** 打开开发者工具
3. 查看 **Console** 面板，应看到：`[布局修复] 检测到布局偏移 Xpx，自动修复`
4. 检查页面顶部和底部是否对齐正常
5. 对比 Edge/Chrome 中的效果，应完全一致
