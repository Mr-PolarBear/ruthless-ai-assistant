# 代码预览侧边栏功能说明

## 1. 功能概述

代码预览侧边栏（Code Preview Sidebar）旨在提供更好的代码阅读体验，特别是当 AI 输出长篇代码时。它能自动将正在生成的代码块“投影”到右侧独立区域，支持语法高亮、实时跟随、以及从主信息流中独立出来的滚动阅读。

## 2. 核心交互逻辑

### 2.1 自动跟随 (Auto-Expand & Live Sync)
- **触发条件**：
  - 用户在设置中开启了“生成时自动展开侧边栏代码”。
  - AI 正在进行流式输出（`isStreaming: true`）。
  - 当前输出的内容包含代码块（`.code-block-container`）。
  - 当前会话 ID 与正在流式生成的会话 ID 一致（防止后台生成的会话干扰前台）。
- **行为**：
  - 侧边栏自动打开，并显示当前正在生成的代码块副本。
  - 内容、高亮类名、语言标签会与主界面实时同步。
  - 侧边栏会自动滚动到底部，保持最新内容可见。

### 2.2 防打扰锁 (Interaction Lock)
- **触发条件**：用户在侧边栏内进行了任何交互操作（点击、滚动、按键）。
- **行为**：
  - 自动滚动停止。
  - 状态栏显示“已解除实时跟随”和“恢复跟随”按钮。
  - 即使代码继续生成，侧边栏也不会再强制滚动到底部。

### 2.3 恢复跟随
- **操作**：点击状态栏的“恢复跟随”按钮。
- **行为**：
  - 重置防打扰锁。
  - 立即滚动到底部。
  - 恢复实时同步滚动模式。

### 2.4 智能关闭与切换
- **关闭时机**：
  - 手动点击关闭按钮。
  - 开始新一轮对话（发送新消息）。
  - 切换会话（点击历史记录）。
  - 检测到当前代码块变为了 `tool_call`（MCP工具调用不展示在侧边栏）。
- **切换会话防御（防诈尸机制）**：
  - **抑制锁 (`suppress`)**：切换会话时，系统会开启 800ms 的抑制锁，期间禁止任何自动展开请求。
  - **DOM 连接性检查 (`isConnected`)**：`tryAutoExpand` 会检查目标代码块是否仍存在于当前文档流中。如果因为切换会话被清空了，则拒绝展开。
  - **会话一致性检查**：严格比对 `currentConversationId` 和 `streamingConversationId`。

## 3. 技术实现细节

### 3.1 核心模块 (`js/code-preview-manager.js`)
- **单例模式**：全局管理侧边栏状态。
- **MutationObserver**：监听 Shadow DOM 中的原始代码块变化，同步到侧边栏的克隆节点。
- **requestAnimationFrame**：用于优化滚动逻辑，避免高频 DOM 更新导致的页面抖动。
- **自动滚动追底**：跟随模式下（`userInteracted === false`），每次 MutationObserver 回调都会通过 `requestAnimationFrame(() => contentArea.scrollTop = contentArea.scrollHeight)` 无条件追底。用户交互后（`userInteracted === true`）则完全停止自动滚动。

### 3.2 关键函数
- `tryAutoExpand(blockId, container, isStreaming)`: 决策是否展开侧边栏。这是所有逻辑的入口，包含多重防御机制。
- `setupLiveSync(original, clone)`: 建立主界面与侧边栏的镜像同步关系。
- `suppress(duration)`: 暂时禁用自动展开，处理异步竞态条件。

### 3.3 与渲染管线的集成
- 在 `js/renderers/stream-renderer.js` 中，当 DOM 更新时调用 `tryAutoExpand`。
- 通过 `isStreaming` 参数区分“流式生成”和“历史记录渲染”，防止加载历史消息时侧边栏乱跳。

## 4. 常见问题排查

- **Q: 为什么切换会话时侧边栏有时候会闪现？**
  - A: 这是异步渲染导致的竞态问题。已通过 `suppress(800)` 和 `isConnected` 检查彻底修复。
- **Q: 为什么 MCP 工具调用的 JSON 不显示在侧边栏？**
  - A: 设计如此。`tryAutoExpand` 会检测 `language-tool_call` 类名并拦截，因为工具调用通常不需要代码预览体验。
- **Q: 为什么侧边栏内容在增长但不会自动滚到底部？**
  - A: 检查 `code-preview.css` 中 `.code-preview-content .code-block-container` 的 `height` 属性。**必须使用 `min-height: 100%` 而非 `height: 100%`**。`height: 100%` 会把容器高度锁死，导致 `contentArea.scrollHeight === clientHeight`，滚动赋值无效。

## 5. CSS 布局注意事项（⚠️ 必读）

侧边栏的自动滚动能否正常工作，**完全依赖 CSS 布局的正确性**。以下是关键约束，修改时务必注意：

| CSS 选择器 | 关键属性 | 说明 |
|------------|----------|------|
| `.code-preview-content` | `overflow-y: auto; flex-grow: 1;` | **唯一的滚动容器**，JS 中 `getScrollTarget()` 返回此元素 |
| `.code-preview-content .code-block-container` | `min-height: 100%;` | ⚠️ **禁止改为 `height: 100%`**，否则内容不会撑开父容器的 scrollHeight |
| `.code-preview-content .code-block-container pre` | `max-height: none !important; flex-grow: 1;` | 移除了主界面的 400px 限高，允许代码自然增长 |

> **历史教训**：2026-03-23 修复了一个因 `height: 100%` 而导致的自动追底失效 bug。该属性把代码块容器锁死在 `contentArea` 的可视高度内，无论代码多长 `scrollHeight` 都不会增加，`scrollTop = scrollHeight` 永远无效。排查过程中走了多次弯路（误以为是 JS 滚动逻辑或 `getScrollTarget` 返回了错误元素），最终通过调试日志确认 `scrollHeight === clientHeight === 737（固定值）` 才定位到 CSS 是根因。
