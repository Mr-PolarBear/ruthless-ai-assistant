# 滚动与视图锁定机制说明 (v3.4 方向感知与死锁根治版)

**作者**: 乌鸦、小鸡
**更新日期**: 2026-08-18

## 概述

本系统致力于提供流畅、智能、**无阻力感**的滚动体验。核心目标有三个：

1.  **自动追踪**：当AI生成新内容（文本、代码块展开、图片加载）时，若用户正在关注最新消息（滚动条在底部），视图应自动向下滚动。
2.  **滚轮零延迟响应**：用户只要向上滚一下鼠标滚轮，**立刻**停止自动滚动，将控制权交给用户，绝无顿挫与死锁。
3.  **双轨解锁机制**：解锁有两种方式——触底自动解锁，或点击"回到底部"按钮手动解锁。

---

## 核心设计：双保险锁定机制

### 问题背景

在 v3.0 时代，我们用 200ms 防抖来实现"滚轮滚动时锁定"。但实测发现：
- AI 高频渲染（~100ms 一次）时，wheel 事件和 AI 渲染的 throttle 回调会形成时序竞争
- 滚一下可能需要滚 2-3 下才能完全锁定
- 这是因为 JS 事件循环的特性：wheel → scroll → throttle 回调可能在同一个事件循环队列中

### v3.4 解决方案：滚轮方向感知 + 向上硬加锁 + 废除越权覆盖

**文件**: `js/scroll-manager.js`

```javascript
// wheel 滚轮事件：方向感知 + 向上硬阻断
dom.chatMessages.addEventListener('wheel', (e) => {
    const isRollingUp = e.deltaY < 0;

    if (isRollingUp) {
        // 用户明确意图是离开底部查看历史消息，同步立起硬锁
        this.wheelLocked = true;
        this.immediateWheelLock = true;
    } else {
        // 向下滚动：如果已滚到底部附近，立即释放锁定，恢复自动跟随
        if (this.isNearBottom(10)) {
            this.wheelLocked = false;
            this.immediateWheelLock = false;
            this.suppressAutoScroll = false;
        }
    }

    clearTimeout(this.autoUnlockTimeout);
    this.autoUnlockTimeout = setTimeout(() => {
        // 滚动停止 300ms 后，如果在底部才解锁 (5px容差)
        if (this.isNearBottom(5)) {
            this.wheelLocked = false;
        }
        if (this.isNearBottom(50)) {
            this.suppressAutoScroll = false;
        }
        this.immediateWheelLock = false; // 300ms 后清除同步标志
    }, 300); // 覆盖 Windows 平滑滚动生命周期
}, { passive: true });

// scroll 事件：利用 isScrollingUp 防止微少位移竞争导致的竞争Bug
let lastScrollTop = dom.chatMessages.scrollTop;
dom.chatMessages.addEventListener('scroll', () => {
    const currentScrollTop = dom.chatMessages.scrollTop;
    const isScrollingUp = currentScrollTop < lastScrollTop;
    lastScrollTop = currentScrollTop;

    wasAtBottom = this.isNearBottom(10); // 严格的10px判断阈值
    
    // 关键优化：仅在向下滚动（或高度激增）且触底时解锁，防止用户向上滚轮时首帧位移过小(<5px)导致的错误解锁（微阻塞现象）
    if (!isScrollingUp) {
        if (this.isNearBottom(5)) {
            clearTimeout(this.autoUnlockTimeout);
            this.wheelLocked = false;
            this.immediateWheelLock = false;
            this.isUserScrolling = false;
        }
        if (this.isNearBottom(50)) {
            this.suppressAutoScroll = false;
        }
    }
}, { passive: true });
```

| 标志 | 类型 | 作用 | 清除时机 |
|------|------|------|----------|
| `wheelLocked` | 异步 | 300ms 保护期，阻断 ResizeObserver 等异步事件 | 触底向下滚动时立即清除 或 300ms 后检查在底部才清除 |
| `immediateWheelLock` | **同步** | 同一事件循环内生效，阻断已在 throttle 队列中的 AI 渲染 | 300ms 后清除 |

### 关键：AI 渲染直接委托 smartScrollToBottom 网关

**文件**: `js/services/llm-service.js`

```javascript
const throttledRender = throttle(async (...) => {
    // 渲染前捕获底部状态——渲染后 scrollHeight 已变，isNearBottom 永远失效
    const wasAtBottom = scrollManager.isNearBottom(10);

    // await 确保 DOM 渲染完成后再滚动，避免夹在高度抖动期间
    await renderFormattedContent(...);

    // — 为什么不再做外部 shouldBlockAutoScroll 检查 —
    // v3.2 时代有外部 if (!shouldBlockScroll) 门控 + smartScrollToBottom 内部门控 = 双重门控，
    // 导致 forceIfWasAtBottom 永远无法覆盖 wheelLocked，用户快速滚到底部时闪烁。
    // v3.3 移除外部门控，统一由 smartScrollToBottom 内部决策。
    scrollManager.smartScrollToBottom(wasAtBottom);
}, 100);
```

## 关键属性与方法说明

### `ScrollManager` 核心字段

| 字段 | 类型 | 作用/生命周期 |
|---|---|
| `isUserScrolling` | `boolean` | 物理阻断锁。鼠标拖拽/手指滑动时为 `true`，松开后 `false`。 |
| `wheelLocked` | `boolean` | 滚轮锁定锁。滚轮滚动后设为 `true`，触底或 150ms 后在底部才清除。 |
| `immediateWheelLock` | `boolean` | **同步急停锁**。滚轮滚动后设为 `true`，150ms 后自动清除。不被消费，持续有效。 |
| `autoUnlockTimeout` | `number` | 滚动停止后的自动解锁定时器 ID。 |
| `suppressAutoScroll` | `boolean` | 逻辑阻断锁。跳转楼层时设为 `true`，点按钮后解除。 |
| `mcpExecutionStates` | `Map` | MCP 高度保持锁。工具调用期间独立管理状态。 |

### `shouldBlockAutoScroll()`

统一检查所有锁定标志，返回 `true` 表示禁止自动滚动：

```javascript
shouldBlockAutoScroll() {
    return this.suppressAutoScroll ||
           this.immediateWheelLock ||
           this.isUserScrolling ||
           this.wheelLocked;
}
```

### `smartScrollToBottom(forceIfWasAtBottom)`

统一的滚动网关。AI 渲染调用此方法决定是否自动滚动：

```javascript
smartScrollToBottom(forceIfWasAtBottom = false) {
    if (this.suppressAutoScroll) return false;

    // — 为什么这么写 —
    // 1. immediateWheelLock 是同步急停，forceIfWasAtBottom 绝对不可覆盖
    // 2. isUserScrolling 是物理拖拽/触摸操作，forceIfWasAtBottom 绝对不可覆盖
    // 3. wheelLocked 是滚轮锁：只要用户向上滚了轮，坚决不抢夺控制权，forceIfWasAtBottom 绝对不可覆盖！
    //    此前允许 forceIfWasAtBottom 覆盖 wheelLocked 导致了 AI 流式输出期间向上回滚在 16ms 内被强制拉回底部、造成死锁。
    //    现在向下滚动由 wheel 事件的 deltaY > 0 + isNearBottom(10) 和 scroll 事件自然解锁，不再需要特权覆盖！
    if (this.immediateWheelLock) return false;
    if (this.isUserScrolling) return false;
    if (this.wheelLocked) return false;

    if (forceIfWasAtBottom || this.isNearBottom(10)) {
        scrollToBottom();
        // 流式渲染 DOM 重建瞬间高度先塌后升，单次 scrollTo 容易夹在抖动里，
        // rAF 在下一帧（高度恢复后）再补滚一次
        requestAnimationFrame(() => scrollToBottom());
        return true;
    }
    return false;
}
```

### `forceScrollToBottom()`

强行滚到底部，并清除所有锁定标志：

```javascript
forceScrollToBottom() {
    this.suppressAutoScroll = false;
    this.wheelLocked = false;
    this.immediateWheelLock = false;
    this.isUserScrolling = false;  // v3.3：也清除拖拽锁
    clearTimeout(this.autoUnlockTimeout);
    scrollToBottom();
    // v3.3：rAF 补滚，与 smartScrollToBottom 一致，防止渲染抖动
    requestAnimationFrame(() => scrollToBottom());
}
```

## 解锁机制

| 解锁方式 | 触发条件 | 清除哪些标志 |
|----------|----------|--------------|
| **触底自动解锁（物理锁）** | scroll 事件检测到 `!isScrollingUp && isNearBottom(5)` | `wheelLocked`, `immediateWheelLock`, `isUserScrolling` |
| **触底自动解锁（逻辑锁）** | scroll 事件检测到 `!isScrollingUp && isNearBottom(50)` | `suppressAutoScroll` |
| **按钮手动解锁** | 点击"↓回到底部"按钮 | 全部标志（含 `isUserScrolling`） |
| **超时自动解锁（物理锁）** | 滚动停止 300ms 后 `isNearBottom(5)` | `wheelLocked` |
| **超时自动解锁（逻辑锁）** | 滚动停止 300ms 后 `isNearBottom(50)` | `suppressAutoScroll` |
| **拖拽自动解锁** | 鼠标拖拽滚动条后松开（手指离开触屏） | `isUserScrolling` |

> **为什么物理锁和逻辑锁阈值不同？**
> - 物理锁（`wheelLocked` 等）严格 5px：用户向上微偏一格平滑滚动时，首帧位移 <5px 会被误判为"依旧在底部"而强行解锁，产生微回拉幽灵 bug
> - 逻辑锁（`suppressAutoScroll`）宽松 50px：流式输出期间 scrollHeight 持续增长，用户视觉上滚到底部但代码判定可能差几十像素，严格 5px 会导致永远清不掉

## 场景行为矩阵

| 用户场景 | 系统反应 | 内部机理 |
|---|---|---|
| **AI 输出中，当前视口在最底部** | 🤖 自动如丝般顺滑推着往下走 | 所有锁定标志为 `false` → 执行滚动 |
| **AI 输出中，用户滚了一下鼠标滚轮** | 🛑 瞬间停止，零顿挫 | `immediateWheelLock=true` + `wheelLocked=true` → 阻断所有自动滚动 |
| **用户滚了一下后继续滚** | 🛑 继续保持锁定 | `wheelLocked` 持续为 `true` |
| **AI 输出中，用户快速滚到底部** | 🚀 无闪烁恢复跟随 | `wasAtBottom=true` → `forceIfWasAtBottom` 覆盖 `wheelLocked` → 滚动 |
| **滚到历史记录后手滑到底部** | 🚀 触底自动解锁，恢复跟随 | scroll 事件检测到触底 → 清除所有锁定 |
| **滚到历史记录后不慎触底又弹开** | 🛑 保持锁定，AI 不跟随 | 触底时间太短，AI 渲染时已不在底部 |
| **跳转至某楼层** | 🛑 防止弹窗效应，停在跳转处 | `suppressAutoScroll=true` 逻辑锁死 |
| **跳转后，滚到接近底部** | 🚀 50px 阈值内恢复跟随 | `isNearBottom(50)` → 清除 `suppressAutoScroll` |
| **跳转后，点击"↓回到底部"按钮** | 🚀 一拉到底，恢复一切自动跟随 | `forceScrollToBottom` 清除所有锁并执行滚动 |
| **按住滚动条往上拖** | 🛑 绝对控制权移交用户 | `isUserScrolling=true` 物理锁死 |

## 历史演进日志

*   **v1.0 (基础时代)**: 依赖 `MutationObserver` 和 `setTimeout` 延迟滚动，容易出现抖动和时序错乱。
*   **v2.0 (状态机时代)**: 引入 `scrollIntention` 和 `lastUserScrollTime` 等防抖参数，试图区分"程序滚动"和"用户滚动"。但在极端流式高频测试中，暴露出异步 `scroll` 事件互相踩踏导致的"滚轮顿挫阻力感"。
*   **v3.0 (黄金极简时代)**: 返璞归真。废弃一切意图猜测，通过底层 `ResizeObserver` + `wasAtBottom` 穿透传参构建"锚点跟随"模型。达成真正 0 顿挫的高优体验。
*   **v3.1 (滚轮优先时代)**: 引入 `immediateWheelLock` 同步急停锁 + `wheelLocked` 异步锁的双保险机制，解决高频 AI 渲染时 wheel 事件时序竞争的问题。AI 渲染前主动查询锁定状态，确保滚轮一滚就立即响应。
*   **v3.2 (极致丝滑时代)**: 引入 `isScrollingUp` 滚动方向雷达。大幅收紧 `isNearBottom` 容差判定（150px -> 10px），并延长打断锁保护时间（150ms -> 300ms）以完美覆盖 Windows 平滑滚动动画周期。同时在 `scroll` 事件中通过对首帧向上细微位移的阻断，彻底排除了平滑滚动竞争，根治了滚轮微阻塞和被内容反向拉回的“幽灵Bug”。
*   **v3.3 (消除闪烁时代)**: 根治"手动快速滚到底部时闪烁"问题。核心改动：
    1. **消除双重门控**：移除 `llm-service.js` / `reasoning-renderer.js` 中外部的 `shouldBlockAutoScroll()` 检查，统一由 `smartScrollToBottom` 内部决策。此前外部 `if (!shouldBlockScroll)` + 内部 `if (this.wheelLocked)` 双重门控，导致 `forceIfWasAtBottom` 永远无法生效。
    2. **forceIfWasAtBottom 覆盖 wheelLocked**：`smartScrollToBottom` 中 `wheelLocked` 可被 `forceIfWasAtBottom` 覆盖（`if (this.wheelLocked && !forceIfWasAtBottom) return false`），因为"渲染前就在底部"的语义优先级高于"用户滚过轮"。但 `immediateWheelLock` 和 `isUserScrolling` 仍不可覆盖（物理操作优先）。
    3. **分离物理锁/逻辑锁阈值**：`wheelLocked` 严格 5px 解锁，`suppressAutoScroll` 宽松 50px 解锁，解决楼层跳转后流式输出期间难以恢复跟随的问题。
    4. **rAF 补滚**：`smartScrollToBottom` 和 `forceScrollToBottom` 均增加 `requestAnimationFrame(() => scrollToBottom())`，覆盖流式渲染 DOM 重建瞬间高度先塌后升的抖动。
    5. **throttledRender await 渲染**：`renderFormattedContent` 改为 `await`，确保 DOM 渲染完成后再触发滚动，避免夹在高度抖动期间.
*   **v3.4 (方向感知与死锁根治版)**: 根治"AI 流式输出期间向上回滚纹丝不动死锁"问题。核心改动：
    1. **滚轮方向感知（deltaY < 0）**：向上滚轮为硬加锁，坚决不被自动滚动拉回；向下滚轮（deltaY > 0）在接近底部时即时释放锁定，恢复自动跟随。
    2. **废除 forceIfWasAtBottom 越权覆盖**：彻底移除 `smartScrollToBottom` 中 `forceIfWasAtBottom` 对 `wheelLocked` 的覆盖特权，从底层消除 0ms 钳制死锁。
    3. **自杀式清锁防御**：`scrollToBottom` 不再能反向冲垮用户的向上滚轮锁，向上回滚获得绝对控制权。
